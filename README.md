# my-dashboard

会社モニターに出しっぱなしにしておくための個人用ダッシュボード。
予定・天気・相場・時計を、暗い背景の1画面にまとめて表示する。

要件の経緯は `生成物/personal-dashboard/要件定義書.md` にある。

## 画面

```
┌─────────────────────────────────────────────────────────┐
│ 時計（時・分・秒＋日付・曜日）              取得状況     │
├──────────┬────────────┬─────────────────┬───────────────┤
│ 昭島市   │  天気：昭島｜台東｜鹿沼                       │
│ 週間天気 ├──────┬──────┬────────────────┤  相場         │
│ （7日）  │来客・│タスク│ 今日の予定（広め） │ （widget×6）  │
│雨雲レーダ│外出  │      │                  │               │
│ 鹿沼市   ├──────┴──────┴──────┬─────────┤  チャートへ   │
│ 週間天気 │これからの一週間 │カレンダー│               │
│雨雲レーダ│                │（Google  │               │
│ 運行情報 │                │ 埋め込み）│               │
│（リンク）│                │          │               │
└──────────┴────────────────┴─────────┴───────────────┘
```

来客・外出とタスクは「今日の予定」の左に横並びで置き、今日の予定の欄を広めに取っている。
会議欄は廃止した（来客・外出のピックアップだけ残している）。**どちらも今日ぶんだけを表示する**
（一週間分ではない。一週間分は「これからの一週間」欄で見られる）。

「今日の予定」欄は従来どおりAPI取得のテキスト一覧。**「これからの一週間」の右隣り**に、
**Googleカレンダーの公式埋め込み（週表示、日付の切替え可）**を並べている（2026-08-08〜）。
ただし**閲覧専用**——Googleが認証済みのインタラクティブなカレンダー画面自体は
クリックジャッキング対策でiframe埋め込みをブロックしているため、公式に埋め込める
「閲覧専用ウィジェット」の方を採用した。編集したいときは、別タブでGoogle Calendarを
開く必要がある。埋め込みURLに必要なカレンダーID（実質メールアドレス）はリポジトリに
書かず、既存のOAuthトークンで実行時に取得している（詳細はHANDOFF.md「カレンダー埋め込み：
『これからの一週間』の右隣りに設置」参照）。取得できなかった場合は「読み込み中」の
プレースホルダーのままになる（次回ポーリングで自動的に再試行する）。

左サイドの週間天気（昭島市・鹿沼市）の下には、Yahoo!の雨雲レーダー画像を1枚ずつ
表示している（2026-08-08〜）。こちらは静的な`<img>`（Yahoo!静止画地図API）なので
iframeの埋め込み制限は関係ない。利用には別途Yahoo!デベロッパーネットワークでの
無料登録が必要（下記「準備」の「5. 雨雲レーダー」参照）。

来客・外出への振り分けは、タイトルに「来客」「外出」を含むか（`visitorKeywords`）、
または説明欄に「Powered by 駅すぱあと」を含むか（`visitorDescriptionMarkers`）で判定する。
後者は経路検索連携で自動生成された移動の予定を拾うためのもの。どちらも `js/config.js` で調整できる。

タスクは Google Tasks のデフォルトリスト（`@default`）から、**今日が期限のもの**だけを表示する
（期限なし・今日以外のタスクはここには出ない）。Calendarとは別のAPI・別のOAuthスコープ
（`tasks.readonly`）が必要（下記「準備」参照）。

運行情報（中央線・青梅線・銀座線）はリンク自体は公式ページへの直接リンクのまま。
そのうえで、5分ごとに簡易ステータス（平常運転かどうか）だけを取得し、異常があるときだけ
リンクの色を変える（プッシュ的な気づき方を実現するため。2026-08-07、Hideの要望で追加）。
詳しい文言は出さない。異常に気づいたらリンクを押して公式ページで確認する、という
使い方を想定している。

取得経路は路線によって2通りある（2026-08-08〜）:

- **銀座線:** GitHub Actionsが東京メトロの公式JSONを5分ごとcronで直接取得
- **中央線・青梅線:** GitHub ActionsのランナーがAkamaiにブロックされ直接取得できないため、
  ジョルダンの運行情報メールをGoogle Apps Script（Gmail監視）で検知し、GitHub Actionsに
  中継する方式にしている（下記「4. 運行情報（ジョルダンのメール検知）を設定する」参照）

データ源については「気をつけていること」も参照。

相場（ドル円・日経平均・XRP・XLM・金・銀）は、すべて **TradingViewのウィジェット埋め込み**
（`embed-widget-single-quote.js`）で表示している。`https://iroha-ai.github.io/realtime-charts/`
と同じシンボル・同じ仕組み。無料の価格取得APIをいくつも使い分けていた旧実装（CoinGecko・
gold-api.com・Twelve Data・GitHub Actions cron）は撤去し、TradingViewに一本化した。
ウィジェット自身がリアルタイム更新するので、このダッシュボード側での取得処理も鮮度管理も無い。

## 構成

ビルド手順はない。素の HTML・CSS・JavaScript をそのまま GitHub Pages に置く。

```
[GitHub Actions cron・5分ごと・終日]
   └→ 銀座線を取得 → data ブランチの train.json へ上書き（train.yml）

[ジョルダン運行情報メール] → [Google Apps Script（Gmail監視・5分おき）]
   └→ repository_dispatch → data ブランチの train-mail.json へ上書き（train-mail.yml）
      （中央線・青梅線。新着メールが無くても5分おきに必ず1回送る＝ハートビート）

[モニター用PCのブラウザ]
   ├→ 画面本体・相場ウィジェット : GitHub Pages + TradingView埋め込み
   ├→ 天気                      : 気象庁＋Open-Meteo（30分ごと）
   ├→ 予定・タスク               : Google Calendar API / Tasks API（5分ごと）
   └→ 運行情報リンクの色         : train.json（銀座線）+ train-mail.json（中央線・青梅線）
                                    どちらも raw.githubusercontent.com 経由、5分ごと
```

GitHub Actionsのcronは運行情報（銀座線）の取得のみに使っている（相場データ取得用のcronは
TradingViewウィジェット化にともない撤去した）。中央線・青梅線はcronではなく、
Google Apps Script側からのイベント駆動（repository_dispatch）で更新される。

予定・タスクはブラウザと Google の間だけで完結し、リポジトリを経由しない。
公開リポジトリでも来客名や社内の予定が外に出ないのは、この形にしているため。

## 準備

### 1. Google カレンダー・タスクに繋ぐ

1. Google Cloud コンソールでプロジェクトを作り、**Google Calendar API** と
   **Google Tasks API** の両方を有効にする
2. 「OAuth 2.0 クライアント ID」を**ウェブアプリケーション**として作成する
3. **承認済みの JavaScript 生成元**に、このダッシュボードのURLを登録する
   - 本番: `https://iroha-ai.github.io`
   - 手元で確認するとき: `http://localhost:8000`
4. 発行されたクライアント ID を `js/config.js` の `googleClientId` に書く
5. 画面右上の「接続する」を押し、`calendar.readonly` と `tasks.readonly` の
   両方の権限を許可する

クライアント ID はブラウザに配られるものなので、公開リポジトリに置いて構わない。
外部から勝手に使われないよう、生成元の限定だけは必ずしておくこと。

**「接続する」は、ブラウザを開き直すたびに毎回押す運用になっている。**
理論上はGoogleにログインしたままなら黙って取り直せるはずだが、実機で確認した
ところサイレントな再取得は毎回失敗し、都度クリックが必要だった（サードパーティ
Cookie制限などが原因と推測。詳しい原因は未調査）。会社モニターの電源を入れ直した
ときだけ一回押す、という運用で割り切っている。押し忘れると、来客・外出／タスク／
今日の予定／一週間の欄がすべて「カレンダーに接続できていません」のままになる。

**Google Tasks APIの有効化は、押した直後にボタンの見た目が変わったか（「API を
無効にする」に変わっているか）を必ず確認すること。** 製品詳細ページの青いチェック
マークは有効化状態の表示ではなくTasksのプロダクトロゴなので、紛らわしい（詳細は
HANDOFF.md参照）。

### 4. 運行情報（ジョルダンのメール検知）を設定する

中央線・青梅線は、GitHub ActionsのランナーがAkamai（Bot対策）にブロックされ、
JR東日本の公式ページを直接取得できない。代わりに、ジョルダン乗換案内の
「運行情報メール」をGoogle Apps Script（GAS）でGmail監視し、GitHub Actionsに
中継する方式にしている。**この設定はコード側の変更だけでは完結せず、以下の
手動作業がHide側で必要。**

1. **ジョルダンの運行情報メールを登録する**
   （<https://mb.jorudan.co.jp/os/annai/usefuluml.html> 参照）。
   対象路線は「中央線（快速）」「青梅線」の2つ。登録先は、次のGASプロジェクトが
   読みにいくGmailアドレス（Hideの通常のGmailアカウントでよい）。
2. **GitHubのPersonal Access Tokenを発行する。**
   **classic PATを使うこと（Fine-grained PATは不可）。** Settings → Developer settings →
   Personal access tokens → **Tokens (classic)** → Generate new token (classic)。
   このリポジトリは公開なので、スコープは `repo` 全部ではなく **`public_repo`** だけで足りる。
   ⚠️ Fine-grained PATは、Contents: Read and writeを付与しても`repository_dispatch`が
   204（成功）を返すのに実際にはワークフローが動かないという既知の不具合があるため使わない
   （詳細はHANDOFF.md「運行情報：中央線・青梅線をジョルダンのメール検知に切替」参照）。
3. **Google Apps Scriptプロジェクトを作る。**
   <https://script.google.com> で新規プロジェクトを作成し、`gas/train-status-watcher.gs`
   の中身をまるごと貼り付ける。
4. **Script Propertiesを設定する。**
   プロジェクトの設定 →「スクリプト プロパティ」で以下を追加:
   - `GITHUB_TOKEN`: 手順2で発行したトークン
   - `GITHUB_REPO`: `iroha-ai/my-dashboard`
5. **`installTrigger` を一度だけ手動実行する。**
   GASエディタで関数 `installTrigger` を選んで実行ボタンを押す。初回は
   Gmail読み取りの権限承認ダイアログが出るので許可する。これで5分おきの
   時間主導型トリガーが設定される。
6. **最初の実メールが届いたら、`gas/train-status-watcher.gs` 冒頭の
   「要検証・要調整」を確認し、`SEARCH_QUERY` / `ROUTE_PATTERNS` /
   `ALERT_KEYWORDS` / `NORMAL_KEYWORDS` を実際の件名・本文に合わせて調整する。**
   現状の値はジョルダンの公式ページの説明からの推測であり、実物のメールでは
   未確認。特に `SEARCH_QUERY` に送信元アドレス（`from:`）を足すと誤検知を
   減らせる。

設定後の反映確認は、GASエディタの実行ログ（実行数）と、GitHub側の
Actions → 「運行情報の更新（ジョルダンのメール検知：中央線・青梅線）」の
実行履歴でできる。うまく動いていれば、新着メールが無くても5分おきに
実行が記録され続ける（ハートビート方式。詳細は`gas/train-status-watcher.gs`内コメント参照）。

### 5. 雨雲レーダー（Yahoo!静止画地図API）を設定する

週間天気（昭島市・鹿沼市）の下に、Yahoo!の雨雲レーダー画像を表示する機能。
コード側は実装済みだが、**Yahoo!デベロッパーネットワークでの無料登録が必要**
（未登録の間は代わりに案内文だけが出る）。

1. <https://e.developer.yahoo.co.jp/register/> でYahoo!デベロッパーネットワークに
   登録し、アプリケーションを1つ作成する（無料。1日あたり5万回までのリクエスト制限）
2. 発行された **Client ID** を控える
3. `js/config.js` の `yahooMapAppId` にそのClient IDを設定する

画像は `https://map.yahooapis.jp/map/V1/static` を直接叩く静止画で、
JSやiframeを使わない単純な `<img>` タグなので、Google Calendarのような
埋め込み制限は無い。緯度経度は`weeklyWeatherCities`（週間天気と同じ設定）を
そのまま使う。

## 手元で動かす

```bash
cd my-dashboard
python3 -m http.server 8000
```

`http://localhost:8000/?demo=1` を開くと、Google に接続しなくても
サンプルの予定・タスクで表示を確かめられる。天気・相場ウィジェットは本物が出る。

`?demo=1` を外すと通常動作になり、実際のカレンダー・タスクを見にいく。

## 気をつけていること

- **予定・タスクの中身はリポジトリに残さない。** 取得結果をファイルに書き出さない
- **取れなかったものは黙って空にしない。** 天気・カレンダー・タスクのいずれかが落ちたら、画面右上に短く出す
- **タスクの取得失敗は、画面上にHTTPステータスとGoogle側のエラーメッセージまで出す。**
  コンソールを開かなくても原因（権限不足・API未有効化など）を判断できるようにするため

## 既知の注意点

- 昭島と台東は気象庁の予報区が同じ「東京地方」なので、**天気の文章は両方同じものが出る**。
  気温は地点ごとの座標で取っているため別々の値になり、注意報も市区町村単位なので別々に出る
- 気象庁の防災情報 JSON は、仕様が公開された API ではない。予告なく変わる可能性を承知のうえで使っている
- **相場（TradingViewウィジェット）は要インターネット接続。** ウィジェット自体が読み込めなかった
  場合、画面右上のステータス表示の対象外なので、空白のまま気づきにくい
- 時計（`js/clock.js`）は `new Date()` のブラウザ／OSローカル時刻をそのまま使っている。
  明示的に `Asia/Tokyo` を指定していないため、モニターPCのタイムゾーン設定に依存する
- **運行情報のデータ源は路線によって異なる。**
  - 銀座線: `https://www.tokyometro.jp/library/common/operation/status.json`（JSONP）。
    東京メトロが自社サイトの表示に使っている内部JSONを直接読む方式
    （`scripts/fetch-train.mjs`）。GitHub Actionsからも問題なく取得できている
  - 中央線・青梅線: **2026-08-08〜、ジョルダンの運行情報メールをGmail監視する方式に
    切替済み**（`gas/train-status-watcher.gs` + `.github/workflows/train-mail.yml`）。
    以前はJR東日本の内部HTML（`traininfo.jreast.co.jp`）を直接読む方式を試みたが、
    **GitHub ActionsからはAkamaiのBot対策でHTTP 403になり取得できなかった**
    （ローカル・ブラウザからは通る）。UA偽装等でのさらなる回避はしない方針のため、
    直接取得は諦め、ジョルダンのメール検知に切り替えた。設定手順は上記
    「4. 運行情報（ジョルダンのメール検知）を設定する」参照。詳細な経緯はHANDOFF.md参照
  - **JR東日本のページには「無断転載、複写または電磁媒体等に加工することを禁じます」との
    記載があるが、中央線・青梅線はもうJR東日本のページを直接読んでいないため該当しない。**
    （ジョルダン側の利用規約は別途確認が必要。個人利用・非公開的な用途〈社内モニター表示、
    色だけの抽出〉の範囲と割り切っている）
  - 当初は非公式・無料の `tetsudo.rti-giken.jp` を使う実装を試みたが、実装時点（2026-08-07）に
    3つの独立したネットワークいずれからも疎通できず撤回した経緯がある（詳細はHANDOFF.md）
  - **ジョルダンのメール検知が止まった場合の切り戻し:** `js/config.js`の
    `trainMailDataUrl`を空文字にするか、`js/train.js`の`updateTrain`から
    該当ソースの取得を外せば、中央線・青梅線のリンクは（色が付かないだけの）
    静的リンク表示に戻る
