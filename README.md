# my-dashboard

会社モニターに出しっぱなしにしておくための個人用ダッシュボード。
予定・天気・相場・時計を、暗い背景の1画面にまとめて表示する。

要件の経緯は `生成物/personal-dashboard/要件定義書.md` にある。

## 画面

```
┌─────────────────────────────────────────────────────────┐
│ 時計（時・分・秒＋日付・曜日）              取得状況     │
├──────────┬────────────┬─────────────────┬───────────────┤
│ 昭島市   │  天気：昭島｜台東｜鹿沼                       │
│ 週間天気 ├──────┬──────┬────────────────┤  相場         │
│ （7日）  │来客・│タスク│ 今日の予定（広め） │ （widget×6）  │
│ 鹿沼市   │外出  │      │                  │               │
│ 週間天気 ├──────┴──────┴────────────────┤  チャートへ   │
│ 運行情報 │  これからの一週間              │               │
│（リンク）│                                │               │
└──────────┴──────────────────────────────┴───────────────┘
```

来客・外出とタスクは「今日の予定」の左に横並びで置き、今日の予定の欄を広めに取っている。
会議欄は廃止した（来客・外出のピックアップだけ残している）。**どちらも今日ぶんだけを表示する**
（一週間分ではない。一週間分は「これからの一週間」欄で見られる）。

来客・外出への振り分けは、タイトルに「来客」「外出」を含むか（`visitorKeywords`）、
または説明欄に「Powered by 駅すぱあと」を含むか（`visitorDescriptionMarkers`）で判定する。
後者は経路検索連携で自動生成された移動の予定を拾うためのもの。どちらも `js/config.js` で調整できる。

タスクは Google Tasks のデフォルトリスト（`@default`）から、**今日が期限のもの**だけを表示する
（期限なし・今日以外のタスクはここには出ない）。Calendarとは別のAPI・別のOAuthスコープ
（`tasks.readonly`）が必要（下記「準備」参照）。

運行情報（中央線・青梅線・銀座線）はライブ取得ではなく、JR東日本・東京メトロの
公式運行情報ページへの直接リンク。理由は「気をつけていること」を参照。

相場（ドル円・日経平均・XRP・XLM・金・銀）は、すべて **TradingViewのウィジェット埋め込み**
（`embed-widget-single-quote.js`）で表示している。`https://iroha-ai.github.io/realtime-charts/`
と同じシンボル・同じ仕組み。無料の価格取得APIをいくつも使い分けていた旧実装（CoinGecko・
gold-api.com・Twelve Data・GitHub Actions cron）は撤去し、TradingViewに一本化した。
ウィジェット自身がリアルタイム更新するので、このダッシュボード側での取得処理も鮮度管理も無い。

## 構成

ビルド手順はない。素の HTML・CSS・JavaScript をそのまま GitHub Pages に置く。

```
[モニター用PCのブラウザ]
   ├→ 画面本体・相場ウィジェット : GitHub Pages + TradingView埋め込み
   ├→ 天気                      : 気象庁＋Open-Meteo（30分ごと）
   ├→ 予定・タスク               : Google Calendar API / Tasks API（5分ごと）
   └→ 運行情報                  : JR東日本・東京メトロの公式ページへのリンク（取得はしない）
```

このダッシュボードは外部データを持たない静的ページで、GitHub Actionsのcronも使っていない
（以前は相場データ取得に使っていたが、TradingViewウィジェット化にともない撤去した）。

予定・タスクはブラウザと Google の間だけで完結し、リポジトリを経由しない。
公開リポジトリでも来客名や社内の予定が外に出ないのは、この形にしているため。

## 準備

### 1. Google カレンダー・タスクに繋ぐ

1. Google Cloud コンソールでプロジェクトを作り、**Google Calendar API** と
   **Google Tasks API** の両方を有効にする
2. 「OAuth 2.0 クライアント ID」を**ウェブアプリケーション**として作成する
3. **承認済みの JavaScript 生成元**に、このダッシュボードのURLを登録する
   - 本番: `https://iroha-ai.github.io`
   - 手元で確認するとき: `http://localhost:8000`
4. 発行されたクライアント ID を `js/config.js` の `googleClientId` に書く
5. 画面右上の「接続する」を押し、`calendar.readonly` と `tasks.readonly` の
   両方の権限を許可する

クライアント ID はブラウザに配られるものなので、公開リポジトリに置いて構わない。
外部から勝手に使われないよう、生成元の限定だけは必ずしておくこと。

**「接続する」は、ブラウザを開き直すたびに毎回押す運用になっている。**
理論上はGoogleにログインしたままなら黙って取り直せるはずだが、実機で確認した
ところサイレントな再取得は毎回失敗し、都度クリックが必要だった（サードパーティ
Cookie制限などが原因と推測。詳しい原因は未調査）。会社モニターの電源を入れ直した
ときだけ一回押す、という運用で割り切っている。押し忘れると、来客・外出／タスク／
今日の予定／一週間の欄がすべて「カレンダーに接続できていません」のままになる。

**Google Tasks APIの有効化は、押した直後にボタンの見た目が変わったか（「API を
無効にする」に変わっているか）を必ず確認すること。** 製品詳細ページの青いチェック
マークは有効化状態の表示ではなくTasksのプロダクトロゴなので、紛らわしい（詳細は
HANDOFF.md参照）。

### 2. 相場ウィジェットの銘柄を変える場合

`index.html` の `.market-widgets` 内、各 `tradingview-widget-container` の
`symbol` を書き換える。TradingViewの銘柄コード（例: `OANDA:USDJPY`）が分かれば
APIキーもビルドも不要。現在の6銘柄:

| 表示順 | 銘柄 | シンボル |
|------|------|------|
| 1 | ドル円 | `OANDA:USDJPY` |
| 2 | 日経平均 | `OANDA:JP225USD` |
| 3 | XRP/USD | `COINBASE:XRPUSD` |
| 4 | XLM/USD | `COINBASE:XLMUSD` |
| 5 | 金（XAU/USD） | `OANDA:XAUUSD` |
| 6 | 銀（XAG/USD） | `OANDA:XAGUSD` |

### 3. GitHub Pages を有効にする

Settings → Pages で、`main` ブランチのルートを公開する。

## 手元で動かす

```bash
cd my-dashboard
python3 -m http.server 8000
```

`http://localhost:8000/?demo=1` を開くと、Google に接続しなくても
サンプルの予定・タスクで表示を確かめられる。天気・相場ウィジェットは本物が出る。

`?demo=1` を外すと通常動作になり、実際のカレンダー・タスクを見にいく。

## 気をつけていること

- **予定・タスクの中身はリポジトリに残さない。** 取得結果をファイルに書き出さない
- **取れなかったものは黙って空にしない。** 天気・カレンダー・タスクのいずれかが落ちたら、画面右上に短く出す
- **タスクの取得失敗は、画面上にHTTPステータスとGoogle側のエラーメッセージまで出す。**
  コンソールを開かなくても原因（権限不足・API未有効化など）を判断できるようにするため

## 既知の注意点

- 昭島と台東は気象庁の予報区が同じ「東京地方」なので、**天気の文章は両方同じものが出る**。
  気温は地点ごとの座標で取っているため別々の値になり、注意報も市区町村単位なので別々に出る
- 気象庁の防災情報 JSON は、仕様が公開された API ではない。予告なく変わる可能性を承知のうえで使っている
- **相場（TradingViewウィジェット）は要インターネット接続。** ウィジェット自体が読み込めなかった
  場合、画面右上のステータス表示の対象外なので、空白のまま気づきにくい
- 時計（`js/clock.js`）は `new Date()` のブラウザ／OSローカル時刻をそのまま使っている。
  明示的に `Asia/Tokyo` を指定していないため、モニターPCのタイムゾーン設定に依存する
- **運行情報（中央線・青梅線・銀座線）はライブ取得をやめ、公式ページへのリンクにしている。**
  当初 `tetsudo.rti-giken.jp`（非公式・無料API）でライブ取得する実装を試みたが、実装時点（2026-08-07）に
  このAPIへ3つの独立したネットワーク（開発環境・実ブラウザ・GitHub Actions）いずれからも疎通できず、
  サービス自体が終了している可能性が高いと判断して撤回した。復活や代替の無料APIが見つかれば、
  ライブ取得に戻す余地はある
