# my-dashboard

会社モニターに出しっぱなしにしておくための個人用ダッシュボード。
予定・天気・相場・時計を、暗い背景の1画面にまとめて表示する。

要件の経緯は `生成物/personal-dashboard/要件定義書.md` にある。

## 画面

```
┌─────────────────────────────────────────────────────────┐
│ 時計（時・分・秒＋日付・曜日）              取得状況     │
├──────────┬──────────────────────────────┬───────────────┤
│ 昭島市   │  天気：昭島｜台東｜鹿沼                       │
│ 週間天気 ├────────────┬─────────────────┤  相場         │
│ （7日）  │ 来客・外出 │  今日の予定（広め） │  日経(widget) │
│          │            │                  │  最新価格     │
│          │            │                  │  最終更新     │
│ 運行情報 ├────────────┴─────────────────┤  チャートへ   │
│ 中央線   │  これからの一週間              │               │
│ 青梅線   │                                │               │
│ 銀座線   │                                │               │
└──────────┴──────────────────────────────┴───────────────┘
```

来客・外出は「今日の予定」の左に横並びで置き、今日の予定の欄を広めに取っている。
会議欄は廃止した（来客・外出のピックアップだけ残している）。

来客・外出への振り分けは、タイトルに「来客」「外出」を含むか（`visitorKeywords`）、
または説明欄に「Powered by 駅すぱあと」を含むか（`visitorDescriptionMarkers`）で判定する。
後者は経路検索連携で自動生成された移動の予定を拾うためのもの。どちらも `js/config.js` で調整できる。

運行情報（中央線・青梅線・銀座線）はライブ取得ではなく、JR東日本・東京メトロの
公式運行情報ページへの直接リンク。理由は「気をつけていること」を参照。

日経平均は無料の価格取得APIが見つからなかったため、TradingViewのウィジェット
（`embed-widget-single-quote.js`、realtime-chartsと同じ仕組み）を相場欄に埋め込んでいる。
他の5銘柄（ドル円・XRP・XLM・金・銀）は従来どおり `market.json` 経由。

## 構成

ビルド手順はない。素の HTML・CSS・JavaScript をそのまま GitHub Pages に置く。

```
[GitHub Actions cron・5分ごと・終日]
   └→ 相場を取得（キーは Secrets）→ data ブランチへ上書き

[モニター用PCのブラウザ]
   ├→ 画面本体          : GitHub Pages
   ├→ 相場 market.json  : raw.githubusercontent.com（5分ごと）
   ├→ 天気              : 気象庁＋Open-Meteo（30分ごと）
   ├→ 予定              : Google Calendar API（5分ごと）
   └→ 運行情報          : JR東日本・東京メトロの公式ページへのリンク（取得はしない）
```

予定はブラウザと Google の間だけで完結し、リポジトリを経由しない。
公開リポジトリでも来客名や社内の予定が外に出ないのは、この形にしているため。

## 準備

### 1. Google カレンダーに繋ぐ

1. Google Cloud コンソールでプロジェクトを作り、**Google Calendar API** を有効にする
2. 「OAuth 2.0 クライアント ID」を**ウェブアプリケーション**として作成する
3. **承認済みの JavaScript 生成元**に、このダッシュボードのURLを登録する
   - 本番: `https://iroha-ai.github.io`
   - 手元で確認するとき: `http://localhost:8000`
4. 発行されたクライアント ID を `js/config.js` の `googleClientId` に書く

クライアント ID はブラウザに配られるものなので、公開リポジトリに置いて構わない。
外部から勝手に使われないよう、生成元の限定だけは必ずしておくこと。

モニター用PCで Google にログインしたままにしておけば、アクセストークンは黙って
取り直される。取り直せなかったときだけ、画面右上に「接続する」ボタンが出る。

### 2. 相場データを動かす

1. リポジトリの Settings → Secrets and variables → Actions に
   `TWELVEDATA_API_KEY` を登録する（[Twelve Data](https://twelvedata.com/) の無料キー）
2. Actions タブから「相場データの更新」を一度手で実行し、`data` ブランチができることを確認する
3. `js/config.js` の `marketDataUrl` が、自分のリポジトリの `data` ブランチを指しているか確認する

キーを登録しなくても、XRP・XLM・金・銀は取得できる（キー不要の提供元を使っている）。
ドル円はキーが無いと前日終値になる。日経平均はこのAPIキーとは無関係（下記参照）。

| 銘柄 | 取得先 | キー |
|------|--------|------|
| ドル円 | Twelve Data（無ければ Frankfurter の前日終値） | 任意 |
| XRP・XLM | CoinGecko | 不要 |
| 金・銀 | gold-api.com | 不要 |
| 日経平均 | TradingViewウィジェット（`index.html` に埋め込み） | 不要 |

### 3. GitHub Pages を有効にする

Settings → Pages で、`main` ブランチのルートを公開する。

## 手元で動かす

```bash
cd my-dashboard
node scripts/fetch-market.mjs > data/market.json   # サンプルを作る
python3 -m http.server 8000
```

`http://localhost:8000/?demo=1` を開くと、Google に接続しなくても
サンプルの予定とローカルの相場データで表示を確かめられる。天気は本物が出る。

`?demo=1` を外すと通常動作になり、実際のカレンダーと `data` ブランチを見にいく。

## 気をつけていること

- **予定の中身はリポジトリに残さない。** カレンダーの取得結果をファイルに書き出さない
- **相場APIのキーは Secrets に置く。** ワークフローのログにも出さない
- **cron がコミットするのは `market.json` だけ。** 他のデータをこの経路に増やすときは、公開して差し支えないか都度確認する
- **取れなかったものは黙って空にしない。** 天気・相場・カレンダーのいずれかが落ちたら、画面右上に短く出す
- **相場には最終更新時刻を添える。** 取得が止まったまま古い値が生き続けているように見えるのを防ぐため

## 既知の注意点

- 昭島と台東は気象庁の予報区が同じ「東京地方」なので、**天気の文章は両方同じものが出る**。
  気温は地点ごとの座標で取っているため別々の値になり、注意報も市区町村単位なので別々に出る
- 気象庁の防災情報 JSON は、仕様が公開された API ではない。予告なく変わる可能性を承知のうえで使っている
- GitHub のスケジュール実行は、リポジトリが長く動いていないと自動的に止まることがある。相場欄の最終更新時刻で気づけるようにしてある
- **日経平均は `market.json` を経由しない。** Twelve Data無料プランが指数に未対応だったため、
  TradingViewウィジェットの直接埋め込みに切り替えた（要インターネット接続。取得失敗時のステータス表示の対象外）
- **運行情報（中央線・青梅線・銀座線）はライブ取得をやめ、公式ページへのリンクにしている。**
  当初 `tetsudo.rti-giken.jp`（非公式・無料API）でライブ取得する実装を試みたが、実装時点（2026-08-07）に
  このAPIへ3つの独立したネットワーク（開発環境・実ブラウザ・GitHub Actions）いずれからも疎通できず、
  サービス自体が終了している可能性が高いと判断して撤回した。復活や代替の無料APIが見つかれば、
  ライブ取得に戻す余地はある
